Krok 1) Aplikacja zewnętrzna wysyła plik Word wraz z metadanymi do usługi API WebService (metadane: URL do odesłania pliku po zapisie, [obligo] klasyfikację dokumentu: C1, C2, C3, C4). Następnie plik jest przyjmowany i zapisywany. Później tworzona jest nowa wersja Worda (tzw. edytowalna) po to by nie edytować przysłanego pliku tylko jego kopie (dotyczy pliku Word zaś w przypadku pliku PDF ta czynność powinna być pominięta bo tworzy nie użyteczny duplikat). API D2ViewerWebService w odpowiedzi zwraca do aplikacji źródłowej: GuidMaster, GuidVersion (jeśli docx) a jeśli PDF to tylko GuidMaster.

Krok 2) Tryb tylko do odczytu. Aplikacja zewnętrzna posiadając GuidMaster, otwiera na żądanie użytkownika w osobnym oknie GUI edytora, API WebAPI zwraca do GUI edytora zawartość zapisanego pliku. W zależności od typu pliku otwierany jest:
A) PDFViewer dla *.pdf,
B) DocxEditor dla *.docx, *.doc.

Krok 3) Tryb edycji. Aplikacja źródłowa posiadając GuidMaster oraz GuidVersion, otwiera na żądanie użytkownika w osobnym oknie GUI edytora, API WebAPI zwraca do GUI edytora zawartość zapisanej wersji. Użytkownik edytuje treść pliku, czyli pracuje nad zawartością dokumentu.

----------
 API WebAPI w międzyczasie zakłada lock na tym userze.

User 1 — zapis pracy, bez zamykania dokumentu.
Użytkownik zapisuje wprowadzone zmiany:

klika przycisk Zapisz,
albo zapis wykonywany jest automatycznie w tle co 30 sekund.

Ważne: zapis nie kończy pracy, czyli nie zamyka okna GUI edytora.

User 5 — tryb tylko do odczytu / trwa już edycja.
Aplikacja źródłowa otwiera GUI edytora w trybie podglądu po master GUID bazowej wersji.

User 2 — tryb edycji w tym samym czasie.
Aplikacja źródłowa otwiera GUI edytor, a w URI dodatkowo umieszcza GuidVersion.

Użytkownik chciałby edytować dokument, ale obecnie istnieje lock na dokumencie, więc nie może tego zrobić.

Otrzymuje komunikat:

„Ktoś już modyfikuje dokument, zapraszamy później”.

User 1 — zakończenie edycji / unlock.
Aplikacja źródłowa posiadając GuidVersion, zwalnia lock na żądanie.

Alternatywnie User 1 zwalnia lock klikając przycisk Zakończ, co powoduje odesłanie pliku do aplikacji źródłowej pod wskazany adres.

Jeżeli lock nie zostanie zwolniony, to po czasie 1 dnia worker na kolejce odnajduje za-lockowane krotki.

User 69.
Aplikacja źródłowa otwiera GUI edytora po GUID V1.

Użytkownik chciałby edytować dokument, więc robimy lock na tym userze.

DOC2.
Użytkownik zapisuje sobie stan pracy. Dostępny jest też autosave, ale nie kończy on pracy.

Zapis ręczny odbywa się przez przycisk Zapisz.

OKAPI — User 69, DOC2, GUID V1.
Wysyłamy do aplikacji źródłowej:
URL do odesłania,
GUID V1,
plik po zakończonej edycji.

Przycisk Zakończ zdejmuje lock, czyli wykonuje unlock.

User 4.
Aplikacja źródłowa otwiera GUI edytora w trybie podglądu po master GUID bazowej wersji.
OKAPI / DOC2.
Jeżeli aplikacja źródłowa nie działa, wysyłamy dane co 5 minut.
